# ChordCue Windows 桌面版

Windows 版提供独立的和弦谱编辑、播放头、同步节拍器、PDF 导出和局域网跟谱。目标系统为 **Windows 10 22H2（build 19045）或 Windows 11，x64**。Windows 版播放头由本机驱动；读取 Logic Pro 播放头的功能仍属于原 macOS 版。

当前发布验收状态见 [验证记录](docs/VERIFICATION.md)。自动化测试、冻结程序冒烟和 MSI 数据库检查各自覆盖不同内容；真实消费版 Windows、第二台局域网设备和长时间实体音频测试须分别完成。全部发布门槛关闭前，不创建发布 PR 或宣称验收通过。

## 安装与卸载

1. 取得维护者提供的 `ChordCue-<版本>-win-x64.msi`，核对随构建发布的校验信息。
2. 双击 MSI。安装面向计算机上的所有用户，默认目录为 `C:\Program Files\ChordCue`，安装或维护时可能需要管理员权限。
3. 从开始菜单启动 ChordCue。安装器不在结束时自动运行应用；使用已打包程序不需要另外安装 Python。
4. 更新时使用版本号更高的安装包。MSI 设计为阻止降级；同一版本号不应重新发布不同内容。
5. 从 Windows 的“已安装的应用”中卸载。卸载保留用户自行保存的项目和 AppData 中的个人设置。

安装器不修改 PATH、不自动建立防火墙规则、不添加开机启动。应用配置写入用户 AppData，项目保存到用户选择的位置，不写入 Program Files。签名和 SmartScreen 信任情况应以具体构建记录为准，本仓库不将生成 MSI 等同于已签名发布。

## 开始使用

启动时载入项目自带的 MIT 演示和弦，播放停止，本机声音和局域网投放均关闭。新建或打开项目也从停止状态开始。

- 顶部设置曲名、20–300 BPM、1/4–12/4 拍号和 1–100000 个总小节数。分母固定为 4；播放时不能更改拍号。
- “播放”／“暂停”保留当前位置，“停止”返回第 1 小节第 1 拍。点击谱面或拖动位置滑块可以定位。
- “整小节循环”的两个数字表示**包含的起止小节**。例如 5 至 8 会播放第 5–8 小节，然后回到第 5 小节；项目文件内部保存的结束边界为第 9 小节。
- 无循环时，播放在项目结束边界停止。再次播放会从开头开始。开始和恢复播放采用约 400 ms 的准备时间，供本机和浏览器预排首拍。
- “编辑 / 调性”打开输入面板；编辑后点“应用编辑”才更新谱面。错误会显示行号或原因，不会只取有效行悄悄替换项目。

## 输入和弦与调性

每行写“位置 空格 和弦”，空行忽略：

```text
1 Cmaj7
2.3 G/B
3.1.2.120 Am
4 N.C.
```

位置可以是 `小节`、`小节.拍` 或 `小节.拍.分拍.tick`。小节、拍和分拍从 1 开始；一拍为 960 tick，分成 4 个 240 tick 的分拍。规范写法的分拍范围是 1–4，末尾 tick 范围是 0–239。示例 `3.1.2.120` 表示第 3 小节、第 1 拍之后 360 tick。兼容导入可以接收更大的 tick 分量并在同一小节内规范化；越界或重复起点会报错。保存和重新显示不会丢失分拍位置。

“导入和弦文本…”接收上述手动和弦文本；导入先进入编辑器，点“应用编辑”后生效。请先设置足够的总小节数。内部仍保留原 Logic 演示数据解析和乐理对照入口，它们不是 Windows 用户界面的 DAW 导入／同步功能。

“轨道定调”可以自动判断或手动指定；“自动检测转调”与每行“小节 调”的手动转调点用于分段显示，例如 `33 E♭`、`49 Am`。自动结果是启发式分析，可以手动修正。“移调前原调”是用于显示和导出的额外标记。

## 谱面与 PDF

谱面可切换“和弦谱”与“级数谱”，显示调可选择轨道原样、C 调、移调前原调或指定调。显示移调不会改写原和弦事件。重复小节用 `%` 表示；小节中和弦出现前的延续用横线表示。

“导出 PDF”分别提供两种记谱方式，以及轨道原样、C 调、移调前原调、当前显示调四种调式选项。未指定“移调前原调”时，该选项采用原样显示。PDF 使用本地 Qt 绘制，和屏幕共享按分拍位置计算的谱面布局，不需要在线转换服务。

常规 A4 谱面保持每页 4 列、7 行，共 28 小节。和弦起点密集或名称较长时，谱面会列出起拍和完整名称、增加行高，必要时使用标注“续”的后续页，因此页数可能超过按每页 28 小节估算的数量。极长的单个名称若无法在一页内完整排版，会提示缩短名称。

## 本机与浏览器节拍器

勾选“本机声音”或在“节拍器”页点“开启声音”才会启用本机声音。可以选择经典节拍器／鼓机、按拍／八分音符、每格强度和鼓音色、音量及耳机补偿。“试听一拍”会立即生成本设备的测试拍。

优先使用有线耳机。补偿为正值时声音提前，为负值时延后；设备输出时钟估计不能替代实体耳机校准。程序生成节拍声，不播放或转发歌曲音频。

本机音频页在切换标签和最小化时保留 WebEngine 实例；锁屏或系统挂起会暂停播放并关闭本机声音，解锁后需主动恢复。浏览器跟谱页进入后台时会停声，回来后需重新开启。上述后台行为的长时间实体音频验收单独记录于 [验证记录](docs/VERIFICATION.md)。

窗口位置和大小保存在 `%APPDATA%\ChordCue\ChordCue.ini`。节拍器音色、细分、拍点、音量和补偿保存在 `%LOCALAPPDATA%\ChordCue\ChordCue\WebEngine\Storage` 的浏览器存储中；声音开关和局域网投放开关不会作为启动状态恢复。无需修改安装目录内文件。

## 局域网跟谱

点“局域网投放”后，应用才会开始监听并显示本次投放链接。把链接交给同一可信局域网中的参与者；对方在浏览器打开，按需自行开启声音。对方的显示调、记谱方式、音量和拍点只影响自己的设备。

投放接口只提供当前谱面、播放位置和时钟，浏览器不能编辑项目或控制主机播放。链接含本次会话的随机路径；知道链接且能连接主机的人可以读取谱面。它适合个人排练或可信局域网，不是公网账户／权限系统；停止投放后旧链接失效，下次启用生成新链接。

Windows 防火墙如询问网络访问，请按实际可信网络选择。安装器不会自动放行；连不上时检查双方网络、主机地址、防火墙及路由器的设备隔离。共享内容是和弦谱和播放信息，不包含本地项目路径或歌曲音频。源代码层面的连接边界见 [开发与构建](docs/BUILD.md)。

## 项目文件与问题反馈

`.chordcue.json` 是 UTF-8 JSON，当前 `schemaVersion` 为 1，保存和弦事件、调性、速度、拍号、曲长和循环范围。音量、耳机补偿、窗口状态及 LAN 开关不进入项目。打开时先完整校验，通过后才替换当前曲目；未知版本、重复位置、非法数字或范围会被拒绝。保存先写入同目录临时文件并刷新，再原子替换；另存为也拒绝覆盖无法识别的目标文件。取消保存不会继续关闭当前曲目。

反馈问题时附上应用版本、Windows 版本及 build、复现步骤，以及方便公开的最小演示项目。涉及音频时记录输出设备、是否蓝牙、补偿值和是否在后台；涉及安装时保留 MSI 日志。不要把私人项目、局域网会话链接或本机路径作为必需信息上传。
