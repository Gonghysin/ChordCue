DYNAMIC REPLACEMENT AND REBUILDING

The frozen application ships Qt DLLs, PySide extension modules, plugins,
QtWebEngineProcess, WebEngine data and locales as separate files. ChordCue's
code does not statically link Qt. ChordCue imposes no additional restriction
against replacing these libraries, rebuilding, or reverse engineering for
debugging modifications to the libraries; the libraries' own licenses apply.

First copy the entire frozen directory to a user-writable development location
and retain the original installation. Use compatible x64/Qt/PySide ABI versions.
Replace the matching files under lib/PySide6, the related Shiboken files,
plugins, WebEngine executable, resources and locales as a coherent set. Final
paths are determined by the installed payload; mixing unmatched DLLs can fail.
Alternatively install your rebuilt compatible wheel in an isolated Python 3.13
x64 environment, install the matching ChordCue source, and rerun its cx_Freeze
build and smoke procedures from windows/docs/BUILD.md and windows/packaging.
Windows directory permissions and MSI repair may affect a hand-edited copy in
Program Files, which is why a user-writable development copy is recommended.
ChordCue does not require uploading a modified library to its maintainers.

These engineering instructions and notice files are not a claim that a final
distributor's binary/source license review has been completed. Final payload,
source availability and applicable requirements remain release acceptance items.
